# docs/presentation/ — the feature presentation

Three artefacts explaining what SumoSharp adds on top of SUMO, for an audience of technically-oriented
stakeholders *and* engineers who will build against it:

| | What it is |
| --- | --- |
| **`PRESENTATION.md`** | The written companion — the same argument with more prose, and the place where each claim's evidence class is stated. Read this first. |
| **`svg/*.svg`** | 17 diagrams, generated by `gen_svg.py` so they share one visual system and can be regenerated after any correction — **edit the script, not the SVGs**. |
| **`SumoSharp-features.pptx`** | The 22-slide deck, built from the same diagram set by `build_deck.sh`. Not committed — it is a build artefact; run the script. |

```bash
docs/presentation/build_deck.sh          # SVGs -> PNG -> .pptx, then validates and renders QA images
python3 docs/presentation/gen_svg.py     # diagrams only; rewrites docs/presentation/svg/*.svg
python3 docs/presentation/build_page.py  # the single-page HTML reading version, diagrams inlined
```

Everything lands in `docs/presentation/build/` which is git-ignored — the diagrams and the generators
are the committed artefacts, not their output.

### Two things about building the deck that are not obvious

- **The slide head states the title, so each diagram's own title band is cropped off** before it is
  embedded (110 SVG units; the lowest content any diagram draws is y=130). Without that every
  diagram slide is double-titled.
- **LibreOffice cannot load any file in this sandbox** — a plain `.txt` fails too — so the usual
  `soffice` → `pdftoppm` route for visual QA does not work here. `qa_render.py` stands in: it reads
  the *shipped* package with `python-pptx` and redraws the real shape geometry, and measures text
  with real glyph metrics (DejaVu, slightly wider than Calibri, so it errs toward reporting
  overflow that will not happen rather than missing overflow that will).

## The semantic palette — the point is that colour carries meaning

A reader learns this once on the first diagram and every later one reads faster. **Do not break it**;
visual QA caught three slides where promoted pedestrians had been drawn amber, which trains the audience
to misread the one code you want them to learn.

| Colour | Means | Never used for |
| --- | --- | --- |
| **Amber** `F0B429` | vehicles, the car side | anything pedestrian |
| **Teal** `2BB3A3` | pedestrians (low power / ambient) | vehicles |
| **Bright teal + halo** `6FE3D2` | pedestrians **promoted** to high power | vehicles |
| **Violet** `C7A4FF` | the attention / realism-zone construct — neither car nor pedestrian | agents of any kind |
| **White** `F5F7FA` | the untouched SUMO parity core | |
| **Red** `E5534B` | a problem, a limit, a refuted hypothesis | a merely-unfinished feature |
| **Green** `57A773` | a verified, measured outcome | an aspiration |

## Rules that cost time to learn

- **Never space columns with runs of spaces inside one `<text>`.** XML collapses repeated whitespace, so
  the gaps vanish at render time and four stats become one unreadable run-on. Use the `stats()` helper,
  which places each at its own x.
- **Declare an arrow marker for every palette colour, always.** An arrow referencing an undeclared marker
  renders headless in a browser and hard-crashes `cairosvg`.
- **Modular strides are not a scatter.** `(i * 53) % 200` walks a diagonal and `(i * a + b) % n` lays down
  columns; both render as visible lattices rather than crowds. Use the golden-angle placement (inside a
  disc) or the seeded LCG (over a rectangle) already in the script.
- **Label the thing, not just the legend.** The layering rings were initially unlabelled, so the legend
  beside them could not be mapped onto them.

## Provenance of the numbers on these slides

Three different evidence classes appear, and they are deliberately worded differently because they answer
different questions:

1. **Owner-verified routine operation** — 10 000 vehicles + 30 000 pedestrians in the Godot 3-D viewer,
   with headroom on the pedestrian side. Repeated first-hand operation, not a captured run. This is the
   headline scale claim.
2. **Instrumented and reproducible** — 5 000 cars + 20 000 pedestrians at ~114 ms/step; the write-rate
   figures (`docs/MEASURE-WRITE-RATE-RESULTS.md`, instrument `src/Sim.MeasureWriteRate`).
3. **Captured GPU run** — 3 858 cars + 20 726 pedestrians, 0/2000 spikes, p99 = 1.20× p50.

Keep them distinct. Presenting an operational figure as an instrumented one, or the reverse, is the fastest
way to lose a technical audience.
