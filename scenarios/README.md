# scenarios/ — test data index

This directory holds every net/route/golden dataset the repo uses: the numbered parity scenarios that
gate `dotnet test`, and six underscore-prefixed groups that do not (mostly). If you are about to add a
scenario, run a benchmark, or point a demo at a dataset, read this first — the numbered scenarios and the
underscore groups look similar (both are `net.xml` + `rou.xml` + `.sumocfg` directories) but they mean
very different things.

For the doc set this page belongs to see [`../docs/README.md`](../docs/README.md) (the docs index) and
[`../docs/TOOLS.md`](../docs/TOOLS.md) (which runnable tool to point at a scenario). The
committed-vs-ephemeral rule that governs everything below — goldens are committed, the SUMO binary and
`bin`/`obj` are not — is in [`../CLAUDE.md`](../CLAUDE.md).

## What a parity scenario is made of

A representative example, `01-single-free-flow/`:

```
config.sumocfg        input:  SUMO config (net/route refs, step length, integrator, seed)
net.net.xml           input:  the network
rou.rou.xml           input:  routes/vehicles
golden.fcd.xml        output: SUMO's per-timestep trajectory (pos/speed/lane/accel), COMMITTED
golden.state.xml      output: SUMO's saved simulation state at a fixed time, COMMITTED
golden.vtype.json     output: resolved vType defaults, COMMITTED
tolerance.json        per-scenario parity mode + per-attribute tolerances
provenance.txt        which SUMO version/command produced the goldens, + input file hashes
VTYPE_CROSSCHECK.md   (some scenarios) notes on the vType-default cross-check
replay.html           (some scenarios) a pre-rendered Sim.Viz replay -- an OUTPUT, safe to regenerate
```

Some scenarios add more (`golden.state.mid.xml` for a second save point, `golden.summary.xml` /
`golden.statistic.xml` / `golden.tripinfo.xml` for output-format checks, `golden.ensemble/seedNN.fcd.xml`
for statistical-parity scenarios — see below), but inputs vs. `golden.*` outputs vs. `tolerance.json` vs.
`provenance.txt` is the invariant shape. A few scenarios also carry a `VTYPE_CROSSCHECK.md` or their own
`README.md`/`FINDINGS.md` — read those instead of guessing from the filename.

**Two rules that matter more than anything else in this file:**

1. **The goldens ARE the executable spec.** `dotnet test` loads `golden.fcd.xml` / `golden.state.xml` and
   diffs the engine's own run against them — it never invokes SUMO. A fresh clone with no SUMO installed
   must still pass `dotnet test`. Do not hand-edit a `golden.*` file: it is regenerated by
   `scripts/regen-goldens.sh` (which needs SUMO) and the regeneration ends in a commit, not a live
   computation.
2. **`provenance.txt` records the SUMO version that produced the golden.** Compare its `sumo_version=`
   line against the repo-root [`../SUMO_VERSION`](../SUMO_VERSION) file (currently `1.20.0`). A mismatch
   means that scenario's goldens are stale relative to the vendored `/sumo/` source and must be
   regenerated before being trusted.

`tolerance.json` sets `parityMode` (`"exact"` for phase-1 deterministic scenarios — `sigma=0`, fixed
depart, `actionStepLength=1`, ballistic/Euler pinned, no teleport — or `"statistical"` for scenarios with
`sigma>0`, see below), which attributes are compared (`lane`, `pos`, `speed`, …), and the tolerance per
attribute (e.g. `"pos": 0.001`). Read it before assuming two scenarios are held to the same bar.

**Not every numbered directory has goldens.** Two carve-outs exist, both intentional:

- **Behavioral/property fixtures ("Group B" in `docs/DESIGN.md` "Two futures").** `14-external-obstacle`
  and `15-reroute` inject a live external input (an obstacle, a blockage) that by construction cannot
  appear in any offline SUMO run, so there is no `golden.fcd.xml` to diff against. Each carries its own
  `README.md` saying so and naming the behavioral test that gates it instead
  (`RungB1ExternalObstacleTests`, `RungB3RerouteTests`). Do not go looking for a golden here — there isn't
  one, by design.
- **Statistical-parity scenarios.** `17-dawdle-freeflow`, `20-speedfactor-freeflow`, and
  `58-flow-probability` have `sigma>0` and ship a `golden.ensemble/seedNN.fcd.xml` directory (multiple
  seeded SUMO runs) instead of one `golden.fcd.xml`, with `tolerance.json` `"parityMode": "statistical"`
  and mean/std tolerances instead of exact per-step bounds.
- **Behavioral scenarios whose SUMO counterpart is stochastic.** `53-giveway-single`, `54-giveway-multi`,
  `55-giveway-drift`, `56-flow-equiv`, `57-overtake-opposite` and `59-overtake-cooperative` ship without a
  `golden.fcd.xml` (`56`/`57` instead carry several purpose-built `*.rou.xml` variants). **This is
  intentional, and each one has a named gating test** — verified by grep, one test file per scenario:

  | Scenario | Gated by |
  | --- | --- |
  | `53-giveway-single` | `RungER3GiveWayDetectionTests` |
  | `54-giveway-multi` | `RungER4GiveWayMultiLaneTests` |
  | `55-giveway-drift` | `RungER5GiveWayDriftTests` |
  | `56-flow-equiv` | `RungF1FlowEquivalenceTests`, `RungF2bProbabilisticFlowSnapshotTests` |
  | `57-overtake-opposite` | `RungOV4CooperativeShiftTests`, `RungD2ReturnGapTests` |
  | `59-overtake-cooperative` | `RungD3CooperativeOvertakeTests` |

  The *reason* is in the root [`../README.md`](../README.md): SUMO's own give-way is stochastic sublane
  alignment, and opposite-direction overtaking is gated on `lcOpposite` — so neither has a deterministic
  SUMO trajectory to diff against. They are held to a behavioral/property bar instead. **Do not "fix" one
  of these by generating a golden**; the missing golden is the design, and the property test is the spec.

## Numbered scenarios, by what they exercise

89 numbered directories, `01`…`76` (several numbers reused — see "Reused numbers" below). Grouped by
mechanism, not by number, because that is how you'd actually pick one. "What breaks if this regresses" is
the reason the scenario exists, not a full description.

| Group | Scenarios | What breaks if this regresses |
| --- | --- | --- |
| Car-following models | `01-single-free-flow`, `02-two-vehicle-following`, `03-approach-and-stop`, `10-truck-free-flow`, `17-dawdle-freeflow` (statistical), `20-speedfactor-freeflow` (statistical), `21-ballistic-freeflow`, `22-idm-carfollow`, `23-acc-carfollow`, `24-cacc-carfollow`, `25-idmm-carfollow`, `28-actionstep`, `42-ballistic-follow` | Basic Krauss/IDM/ACC/CACC/IDMM gap-keeping, dawdle, speed factor, ballistic integration, sub-second action steps — the floor everything else sits on. |
| Insertion / demand / depart | `04-insertion-spacing`, `05-platoon-shockwave`, `42-symbolic-depart`, `43-vtypedist`, `50-max-depart-delay`, `75-base-depart` | Insertion spacing/shockwave propagation, symbolic depart positions, vType distributions, max-depart-delay backpressure. |
| Lane changing | `06-two-lane-cruise`, `07-keep-right-change`, `36-multihop-lanes`, `37-intraedge-lanechange`, `43-continuous-lanechange`, `45-multilane-keepright-arrival`, `46-convergence-lane`, `49-multilane-keepright` | Keep-right, multi-hop strategic changes, intra-edge/continuous LC, convergence-lane and arrival-lane keep-right. |
| Junctions and right-of-way | `08-junction-straight`, `11-priority-junction`, `26-right-before-left`, `27-allway-stop`, `29-merge-yield`, `31-merge-yield-sym`, `32-roundabout`, `33-roundabout-solo`, `34-keepclear`, `38-keepclear-crosstraffic`, `39-crossjunction-leader`, `40-farrouted-foe`, `41-forced-turn-lane`, `44-multilane-junction-turn`, `53-giveway-single`, `54-giveway-multi`, `55-giveway-drift` | Priority/right-before-left/all-way-stop rules, merge yielding, roundabouts, keepClear, far-routed-foe false positives, forced turn lanes, give-way detection. |
| Traffic lights | `09-traffic-light`, `30-yellow-decision`, `35-actuated-tls` | Fixed and actuated TLS phasing, yellow-phase stop/go decision. |
| Emergency vehicles | `16-emergency-red`, `50-emergency-red-dilemma`, `51-emergency-foe`, `52-emergency-foe-approaching` | `vClass="emergency"` priority overrides and dilemma-zone behavior at red, foe interaction with mixed emergency/passenger traffic. |
| Rail | `47-rail-free-flow`, `48-two-train-following`, `49-rail-bidi-meet`, `50-rail-signal-meet`, `51-rail-crossing`, `52-rail-traction` | `vClass="rail"` free flow/following, bidirectional meets, rail signals, level crossings, traction/acceleration profile. |
| External agents / reactivity (no golden, Group B) | `14-external-obstacle`, `15-reroute` | Live non-SUMO obstacle injection, stop-then-reroute behavior — see the carve-out above. |
| Sublane / lateral | `60-sublane-drift`, `61-sublane-sidebyside`, `62-sublane-overtake`, `63-sublane-overtake-wide`, `64-sublane-keeplatgap`, `65-mixed-sublane` | Sublane model: lateral drift, side-by-side occupancy, lateral overtake and gap-keeping, mixed sublane/laneless traffic. |
| Overtaking (opposite/cooperative) | `12-overtake`, `57-overtake-opposite`, `59-overtake-cooperative` | Overtake detection/execution, oncoming-traffic overtakes, cooperative shift/abort safety (`OV1`-`OV4` `Rung*` tests). |
| Routing and rerouting | `18-strategic-turnlane`, `19-onramp-merge`, `45-reroute-congestion`, `46-reroute-multilane`, `73-reroute-routelength`, `74-reroute-routing-section` | Strategic lane choice ahead of a turn, on-ramp merge, congestion-triggered rerouting, route-length and routing-section edge cases. |
| Flows / demand shape | `13-stopped-leader`, `56-flow-equiv`, `58-flow-probability` (statistical) | Stopped-leader gap holding, `<flow>` vs. explicit-vehicle equivalence, probability-based flow insertion. |
| Parking | `48-parking-depart`, `67-multi-parking`, `68-serve-nocheat`, `69-parkandstay-lc`, `70-parked-passable`, `71-parkandstay-crossedge`, `72-parkstop-maxspeed`, `76-parking-lot-reuse` | `parkingArea`/`<stop>` depart, multi-area parking, honest capacity ("no cheat" service), parked vehicles remaining passable, parking-then-lane-change, parking-lot reuse. |
| Output formats | `44-summary-output`, `66-tripinfo-arrivallane` | `--summary-output` / `--tripinfo-output` field parity, not just FCD. |
| Config / multi-file | `41-multifile-cfg` | Loading a config that splits demand and vType definitions across separate `.rou.xml` files. |

**Ambiguous / low-confidence classification:** `41-forced-turn-lane` sits in Junctions above because it's
a forced-lane-use case at a junction, but it could equally be filed under Lane changing — read its
`.sumocfg`/net if you need to be sure which mechanism a regression there implicates. `56-flow-equiv` and
`58-flow-probability` are filed under Flows rather than Insertion/demand; the line between those two
groups is fuzzy by nature (both are about how vehicles enter the network) so don't over-read the
placement.

### Reused numbers

Several numeric prefixes are reused with different suffixes — they are unrelated scenarios that happen to
share a number, not variants of one scenario:

- `41-forced-turn-lane` vs `41-multifile-cfg`
- `44-multilane-junction-turn` vs `44-summary-output`
- `45-multilane-keepright-arrival` vs `45-reroute-congestion`
- `46-convergence-lane` vs `46-reroute-multilane`
- `47-rail-free-flow` vs `47-teleport-jam`
- `48-parking-depart` vs `48-two-train-following`
- `49-multilane-keepright` vs `49-rail-bidi-meet`
- `50-emergency-red-dilemma` vs `50-max-depart-delay` vs `50-rail-signal-meet`
- `51-emergency-foe` vs `51-rail-crossing`
- `52-emergency-foe-approaching` vs `52-rail-traction`

When referencing one of these in a commit message, PR, or test name, use the **full directory name**, not
the bare number — "scenario 50" is ambiguous across three unrelated fixtures.

### Unnumbered, no goldens

`evac-grid/` and `evac-grid-tls/` are bare net topologies (no route file, no golden) used as the ground
net for the evacuation demo/viewer code (`Sim.Evac`, `Sim.Viewer`'s `EvacOverlay`/`DemoCatalog`,
`Sim.Viz`'s `SceneGen`). They are not parity fixtures.

## The underscore groups

None of these are numbered-scenario replacements. Each is explained below by what it actually contains —
verified by listing files, not by name.

### `_bench/` — 68 MB of the repo's 97 MB of scenario data. NOT a parity surface.

16 subdirectories (`city-30` … `city-15000`, `city-mixed-1k`, `city-organic[-L2]`, `highway-dense`, and
several `*-demo`/`*-showcase` nets). **None of them ship a `golden.*` file.** They exist for throughput,
determinism, and allocation benchmarking (`Sim.Bench`, `Sim.BenchCity`, and the `RungD*` determinism
tests), not for correctness against SUMO.

`Sim.Bench` and the `RungD1BenchmarkDeterminismTests` / `RungD8ParallelDeterminismTests` /
`RungD9ExportObserverTests` suite all run against `_bench/highway-dense`, which **has no SUMO
reference at all.** Its determinism assertion is a re-pinned hash — it proves the engine reproduces its
*own* prior output byte-for-byte across runs/threads, not that the output matches SUMO. Do not cite a
`highway-dense` result as a parity claim; the parity statement is the goldens in the numbered scenarios,
full stop. See `_bench/SCALING.md` for the benchmark's own scaling-curve writeup and known findings (e.g.
the `C4-vi` far-routed-foe false-positive fix it originally surfaced).

### `_ped/` — pedestrian infrastructure, mostly demo/diagnostic, one exception

8 subdirectories, 8.8 MB. Mixed purpose:

- `demo_city/box/` — the live-city demo dataset (buildings, POIs, zones, ped/vehicle nets) driving
  `LiveCityConfig.ForRepoRoot()`. **Hazard:** see below — this is simultaneously a locked regression
  fixture.
- `demo_city/kernel/` — companion kernel data for the same demo.
- `evac-district/`, `poc0-crossing-plaza/`, `roadnet_min/`, `subarea-box/`, `subarea-irregular/`,
  `subarea-pedfrag2/` — demo scenes and pedestrian-subarea test data for the viewer and
  `Sim.Pedestrians.Tests` (`SubareaManifestTests`, `SubareaBoxBakeTests`, `SubareaWeightedDemandTests`).
  No `golden.*` files in any of them — they support behavioral/structural tests (e.g. "does this subarea
  bake produce N zones"), not SUMO trajectory parity.
- `georef_min/` — the one committed, generated, purpose-built 3-D fixture in this group. See the routing
  section and the hazard below.

### `_repro/` — bug-repro nets, no goldens, own docs

9 subdirectories, 6.9 MB. Each is a hand-built or extracted net that reproduces a specific defect
(`c1-perm-turn`, `synthetic-junction[2]`, `saturation-flow`, `signalized-asymmetry`, `sustained-box`,
`arterial-tjunction`, `parking-maneuver`, `synthetic-parity`). None carry `golden.*` files. Several have
their own `README.md`/`FINDINGS.md`/`MECHANISM-STATUS-and-how-to-use.md` (e.g. `c1-perm-turn/`,
`synthetic-junction2/`) — read those rather than this file for what each one pins down.

### `_diag/` — diagnostics, mostly no goldens, but three are gated

8 subdirectories, 1020 KB. Mostly bare net+route diagnostic setups with **no** golden files
(`c4vii-willpass-grid`, `multilane-internal-lc-crash`, `rbl-left-turns`, `wide-swerve`,
`willpass-saturation`) — these back structural/behavioral assertions (stuck-vehicle counts, overlap
counts) in `Sim.ParityTests` (`C4viiWillpassGridDiagTests`, `MultilaneInternalLcCrashDiagTests`,
`RblLeftTurnsDiagTests`, `RungB6LateralEvasionTests`, `WillPassSaturationDiagTests`,
`ContTurnFlagOnGridlockDiagTests`), not FCD diff.

Three subdirectories are the exception and DO carry goldens:
- `cont-turn-sequence/` — full `golden.fcd.xml`/`golden.state.xml`/`golden.vtype.json`/`tolerance.json`;
  `ContTurnSequenceDiagTests` asserts both an internal-junction-lane occupancy sequence AND (in a second
  test) exact `pos`/`speed` parity against the golden.
- `sym-rbl-straight/` — full golden set but **no `tolerance.json`**; `RungSymRblStraightDiagTests` asserts
  `stuck==0`, not FCD parity (its own comment: "not FCD parity — statistical/structural" convention for
  this directory).
- `uturn-contturn-freeze/` — only `golden.fcd.xml` (no state/vtype/tolerance);
  `UturnContTurnFreezeDiagTests` reads it accordingly.

So `_diag` is not uniformly "no reference" — check each subdirectory's own file set before assuming either
way.

### `_fixtures/` — small synthetic inputs, no goldens, one exception

9 entries, 160 KB — the smallest group. `bridge-crossing[-normal]`, `dawdle-single-lane`,
`junction-external-foe`, `routing-diamond`, `rvo-agent`, `rvo-multi`, `speedfactor-independence`,
`speedfactor-single-lane`, plus a loose `sample.fcd.xml`. None carry `golden.*` files — these are small
hand-built inputs feeding unit-level tests (e.g. `routing-diamond` is the same diamond net topology used
behaviorally by `15-reroute`). Read the referencing test file if you need to know exactly what a given
one asserts.

### `_ig/` — three scenes plus its own README

3 subdirectories (`organic`, `round12`, `roundabout`), 340 KB, no golden files, and its own
`_ig/README.md` — read that rather than this section; it is the authority on what these back
(`Sim.IgBridge.Tests`).

## Hazards (verify before you touch any of these)

1. **`scenarios/_ped/demo_city/box/` is BOTH the live-city demo dataset AND a committed regression
   fixture.** `LiveCityConfig.ForRepoRoot()` hardcodes this path and is called by both the interactive demo
   and by tests (`DemoPedYieldInvariantTests`, `HeadOfQueueStallProbeTests`,
   `LongHorizonGridlockDiagTests`, `ArbitraryNetStageATests`, `ExternalNetLoadingTests`,
   `LiveCitySceneTests`, and more). Editing it to make the demo look better silently moves a regression
   baseline. Detaching the two is a known deferred item —
   [`../docs/TASKS-DONE.md`](../docs/TASKS-DONE.md), "Deferred — detach the live-city DEMO data from the
   LOCKED regression fixture" (the plan: give the demo its own `box-live/` copy, keep `box/` locked).
   **CONFIRMED.**

2. **`_bench` is 68 MB of the 97 MB total, and `Sim.Bench` runs `_bench/highway-dense`, which has no SUMO
   reference.** Its determinism hash is a re-pinned tripwire against the engine's own prior output, not a
   verified-correct value. The parity statement is the goldens in the numbered scenarios. **CONFIRMED**
   (no `golden.*` in `_bench/highway-dense/`; `Sim.Bench/Program.cs` and the `RungD1`/`D8`/`D9` tests all
   point at it; none diff against a SUMO output).

3. **`scenarios/_ped/georef_min/` is the small committed georeferenced 3-D fixture** — generated by
   `scripts/gen-georef-fixture.sh` as a synthetic stand-in for a real SumoData cut sub-area (a Geneva box)
   that this repo cannot carry (real cuts run to hundreds of MB and are produced by a pipeline in another
   repo). It is asserted by
   `tests/Sim.LiveCity.Tests/ExternalNetLoadingTests.cs`
   (`Fixture_IsGeoreferenced3DAndFarFromOrigin`) plus `PedElevationRuntimeTests`, `PedElevationRetainTests`,
   `PedElevationsAlongTests`. Use it whenever a test or sample needs real elevation and a far-from-origin
   coordinate frame — the real large georeferenced datasets are not in this repo and must not be depended
   on. **CONFIRMED.**

4. **`scenarios/44-multilane-junction-turn/config.sumocfg` does not pin the integrator.** Every other
   phase-1 scenario sets `<step-method.ballistic value="false"/>` explicitly in `<processing>` (compare
   `01-single-free-flow/config.sumocfg`); `44-multilane-junction-turn/config.sumocfg` has no such element
   and relies on the SUMO default. It passes today — this is a latent tripwire, not a live failure — and
   is already tracked in [`../docs/TASKS-TODO.md`](../docs/TASKS-TODO.md) under "Determinism /
   configuration hygiene". **CONFIRMED** (diffed the two `config.sumocfg` files directly).

## Which scenario should I use?

| Need | Use |
| --- | --- |
| Smallest routable net for a quick experiment or sample | `01-single-free-flow/` (single edge, one vehicle, exact parity) |
| Something with pedestrian infrastructure | `scenarios/_ped/demo_city/box/` (full demo scene — remember hazard 1) or `scenarios/_ped/poc0-crossing-plaza/` for a small crossing-only scene |
| Something that saturates / a dense benchmark | `scenarios/_bench/highway-dense/` (no SUMO reference — throughput/determinism only, not a parity claim) |
| Something with rail | `scenarios/47-rail-free-flow/` (simplest) or `scenarios/50-rail-signal-meet/` / `scenarios/51-rail-crossing/` for signal/crossing interaction |
| Something georeferenced / 3-D | `scenarios/_ped/georef_min/` (the only committed one — see hazard 3) |
| Something with a traffic light | `09-traffic-light/` (fixed phase) or `35-actuated-tls/` (actuated) |
| Something with emergency-vehicle priority | `16-emergency-red/` (simplest) or `51-emergency-foe/` / `52-emergency-foe-approaching/` for mixed-traffic foe interaction |
| Something exercising rerouting on a live external input (no golden) | `15-reroute/` |
| A roundabout | `33-roundabout-solo/` (single vehicle) or `32-roundabout/` (interaction) |
| Sublane / lateral positioning | `60-sublane-drift/` (simplest) |
| Parking with capacity limits | `68-serve-nocheat/` |
